# July 15, 2025

# Overview

Two updates for today.

- For the time being,
  I am not releasing
  the source code just yet.
  - I would prefer to have it
    in a polished state first,
    especially as I intend
    to work on this individually.
  - Additionally, I am still
    debating how to distribute my game.
    I am tempted to release small parts
    of the source code at a time,
    especially for paid extensions.
    - The main config format will still
      be completely open source!
      Its just that the _main implementation_
      may be released more slowly.
      (This seems like a common thing
      creators can do, like with video
      creators with temporarily exclusive content.)
- I took a compromise with the generic arrays:
  I'm just going to do each of them by hand.
  - I _did_ have a working setup with allt.
    these void pointers, but there were
    two big problems.
    1. Clang couldn't optimize it!
       I compared it again and again
       to directly creating the manager loop,
       and _only_ the latter could be
       reliably inlined.
       - I am guessing that clang
         can only do so much?
         Probably the best it could do
         is go with the _direct_
         translation, i.e.,
         writing it all on the stack.
         (This is NOT what we want!)
    2. This was getting hard to follow!
       I was thinking a bit about rust,
       and for larger loops, its idiomatic
       to write the for loop _each_ time
       (and not necessarily use a custom iterator.)
    - In a language without (good) generics,
      this is almost a must. It's hard
      to work with these void pointers,
      and much more difficult to debug
      the normal version!
  - In any case, my goal is still the
    same: _avoid_ undefined behavior.
    - _Some_ optimizations will inline
      a faulty loop (e.g., not checking
      if the value is non-null and
      dereferences it).
    - But this is bad practice and
      unreliable. (Clang
      could do something different on
      the next update!)
    - Anyhow, doing arrays separaratley
      will be correct, though
      using the inline keyword is
      essential. And this whole
      approach still depends on Clang!
