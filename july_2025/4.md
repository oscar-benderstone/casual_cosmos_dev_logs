## Questions
- How to organize the docs?
  - I decided to put spec in there 
  (puts everything in one spot).
  I think that will be easier to access,
  and I imagine most people will want it
  next to the API.
  - I could go crazy with sections.
  How many do I *need*?
  - Links could be *extremely*
  powerful. This deserves its own post. 
  But, in short, I remember seeing spec based programming 
  in the [ladybird browser](https://github.com/LadybirdBrowser/ladybird).
    - Several functions included references
    to web standards. I think this is great,
    and is easier to manage the implementation
    with the API, track bugs, etc.
    - However, there aren't any *actual* links!
    I was a bit surprised, but I could see
    how involved this would be.
    - BUT this is possible with literate programming!
    - Still cooking some ideas, but lots
    of scripts could be made (even involving
    static analysis!)
