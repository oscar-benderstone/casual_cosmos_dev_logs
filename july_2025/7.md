## Accomplished

- I was working in Zed recently
and finally got `static const``
arrays in a loop to be *fully* inlined, IN a function!
  - Before, I either had to:
    - Write out the loops myself,
    which was a bit messy.
    A macro would be BAD to debug here.
    - Put the array at static scope.
    Easier to use, but it can
    be affected by *any* function in
    the compilation unit!
  - Ideally, I would pass `managers`
    as an argument
    and know about *all*
    of its uses.
    - This is the problem with
    the loops before; I could
    keep writing expressions
    that use the array and would
    have to parse them separately!
  - Somehow Zed allowed me to see this!
  I thought this wasn't reproducible.
  - Turns out had to figure out the right
  flag, and (drum roll please): `-O3`!
    - Now, yes, you might say that
    this is dangerous to use.
    But the code is actually *very clear*!
    Just passing in arguments to SDL
    (which aren't inlined - SDL is
    best used as a shared library, anyway).
    - Managers are supposed to have
    `simple` logic, so
    as long as inlining
    works, this is a genuine
    reason to use `-O3` *for
    simple code and debugging*.
      - It might be crazy to say
      that, but the
      compiler *generates*
      what we would have
      written manual!
      And, we don't have
      to debug a missing
      `new/del`!
      (For the highest assurances,
      we could use a static analyzer,
      which is still on my radar).
  - Anyway, this is a nice quality of life feature. Now, I don't need to use macros!
- I've decided to use C23.
  - The biggest feature: `static constexpr`
    - If I use `static constexpr` (which seems like the best use case anyway),
    GCC and clang inline them at `-O0`!
    So basically they are macros/enum variants
    with scope!
    - This is particularly useful
    for strings.
    - Before, I had to pass in `app_title`
    as a global variable,
    or (*sigh*) use it as a macro.
    Now I can stick to a `constexpr`,
    and it works better `const`
    (in this case)!
  - A few quality of life features:
    - Certain types can be used in enums (not just ints!)
    - There's a `nullptr` that's more portable.
    - `_Generic` from C11,
    though I would probably
    restrict this to arrays
    (and yet, those would need macros,
    unfortunately).
  - To get C23 support, and the above idiom, I might as well use clang.
    (And even when compiling to Windows,
  using `clang-cl` with MVSC seems like a great option).
